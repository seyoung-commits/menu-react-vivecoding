# menu-react-vivecoding

React와 Spring Boot로 만든 메뉴 관리 서비스입니다. 메뉴 등록·수정·검색, 사진 업로드,
카카오 로그인, 장바구니와 카카오페이 테스트 결제, AI 메뉴 추천·설명·사진 생성을 제공합니다.

## 주요 기능

- 카테고리·가격·이름 조건으로 메뉴 조회 및 페이지 이동
- 메뉴 재료·설명과 사진을 함께 등록·수정
- OpenAI를 이용한 메뉴 추천: SSE로 답변과 실제 메뉴 카드를 전달
- WebSocket으로 설명 초안·수정, 사진 생성·진행 상태·취소 처리
- 카카오 로그인 세션과 CSRF 검증을 사용하는 AI 기능
- 기본 더미 메뉴 36개와 재료·설명 데이터

## 추가하며 연습한 기능

Spring Data JPA 메뉴 CRUD 실습을 바탕으로, 배운 내용을 직접 연결해 보기 위해 기능을 확장한 프로젝트입니다.
React 화면부터 외부 API, 회원 데이터, 결제 흐름, AI 스트리밍까지 연습한 내용을 모았습니다.
AI 기능은 `phase-3-2`의 기존 구현을 이 프로젝트의 메뉴 데이터와 카카오 로그인 세션에 맞게 이식했습니다.

### 메뉴 조회와 화면 상태

- 조건이 없는 목록은 서버 페이징을 사용하고, 이름·카테고리 조건은 조회 결과를 화면에서 필터링합니다. 가격 검색은 지정 금액 **초과** 조건입니다.
- 검색어·카테고리·가격·정렬·페이지는 URL에 저장해 새로고침이나 뒤로 가기에서도 같은 조건을 확인할 수 있습니다.
- 라이트/다크 모드는 시스템 설정 또는 저장한 선택을 사용합니다. 디자인 토큰 JSON을 CSS로 변환하고 공통 카드·사진·배지·페이지 버튼을 재사용합니다.

### 사진 업로드와 파일 관리

- 사진은 선택 사항이며 등록 전에 미리 보거나 선택을 취소할 수 있습니다. JPG/PNG, 최대 5MB·2천만 화소를 검사합니다.
- 메뉴 정보는 DB에, 사진은 업로드 폴더에 저장합니다. 응답의 사진 주소로 목록·상세에서 이미지를 표시하고, 사진이 없거나 읽히지 않으면 대체 표시를 사용합니다.
- 새 사진 없는 수정은 기존 사진을 유지합니다. 사진 교체·메뉴 삭제 때 이전 파일을 정리하고, DB 저장 실패 때 새로 만든 파일이 남지 않도록 처리합니다.

### 카카오 로그인·프로필·싱크

- 카카오 로그인 후 회원을 DB에 저장하고 사이트 세션을 만듭니다. 같은 앱의 같은 계정은 다시 로그인해도 기존 회원으로 연결합니다.
- 헤더·로그인 결과·내 정보에서 닉네임과 프로필 사진을 표시하고, 재로그인 시 최신 프로필을 반영합니다. 로그아웃은 세션을 정리합니다.
- 카카오싱크를 활성화하면 서비스 약관을 조회해 필수 동의를 확인하고 동의 내역을 DB에 저장합니다. `/terms`는 실습용 약관 화면, `/account`는 회원·동의 내역 화면입니다.
- 장바구니·결제·AI는 서버에서도 로그인 상태를 확인합니다. 변경 요청은 세션과 CSRF 토큰을 사용합니다.

### 장바구니와 테스트 결제

- 장바구니는 회원별로 DB에 저장해서 다시 로그인해도 남아 있습니다. 같은 메뉴는 수량을 합산하며 항목당 수량은 1~99, 회원당 최대 50종입니다.
- 결제 준비 시 현재 메뉴 가격과 주문 가능 상태를 서버에서 다시 확인합니다. 프론트가 보낸 금액이나 회원번호를 결제 기준으로 사용하지 않습니다.
- 단일 메뉴와 장바구니 전체를 카카오페이 테스트 결제로 연결합니다. 서버가 준비한 주문과 승인 응답의 회원·주문·수량·금액이 일치하는지 확인합니다.
- 승인에 성공하면 구매한 장바구니 항목을 정리하고, 취소·실패하면 남깁니다. 결제 도중 다른 탭에서 바뀐 항목은 행 버전을 확인해 보존합니다.
- 결제 준비, 승인, 취소, 실패, 결과 불확실 상태를 화면에서 구분합니다. 결과 화면 새로고침으로 중복 승인하지 않으며, 장바구니 정리 실패는 상태 조회에서 재시도합니다.

### AI 메뉴 추천·설명·사진

- 추천 창에서 요청하면 SSE로 답변을 받고 실제 메뉴 카드를 보여줍니다. 서버가 메뉴 번호, 주문 가능 여부, 요청의 가격 상한을 확인합니다.
- 메뉴 등록·수정에서 WebSocket으로 설명 초안을 만들고 추가 요청으로 고쳐 씁니다. **설명에 적용**을 눌러 폼에 반영합니다.
- AI 사진 생성은 진행 상태와 결과 미리보기를 보여주고 취소할 수 있습니다. 선택한 생성 이미지는 기존 사진 업로드 방식으로 저장합니다.
- 생성 결과는 사용자가 적용·선택하고 최종 등록/수정을 눌렀을 때 메뉴에 저장됩니다. API 키는 서버 환경변수에서만 읽습니다.
- 기본 더미 메뉴의 재료·설명을 변경 SQL로 채웠습니다. 원본 이름과 수정된 메뉴 이름을 지원하고 이미 작성된 내용은 덮어쓰지 않습니다.

### 검증하면서 연습한 내용

- 로그인: 잘못되거나 만료된 state, 취소·중복 콜백, 로그아웃 요청 검증, 재로그인, 프로필·필수 약관 처리
- 사진: 정상 저장·교체·삭제, 잘못된 이미지와 용량 제한, DB 실패 시 파일 정리
- 장바구니·결제: 다른 회원 항목 접근 차단, 중복 담기와 수량 범위, 주문 불가 메뉴, 승인 응답 불일치, 중복 승인과 정리 재시도
- AI: 세션·CSRF 확인, 필드 저장과 길이 제한, 실제 HTTP SSE·WebSocket 연결, 선택적으로 실제 OpenAI 설명·사진 생성과 업로드
- 프론트: lint와 프로덕션 빌드, 로딩·오류 상태와 화면 표시 확인
- 공개 준비: DB 비밀번호와 API 키를 환경변수로 분리하고, 로컬 설정·업로드·생성 파일을 제외했습니다. 의존성 보안 점검에서 발견한 `source-map-js`는 1.2.2로 패치했습니다.

### 현재 실습 범위

결제는 `TC0ONETIME`을 사용하는 테스트 결제입니다. 장바구니와 회원·약관은 DB에 저장하지만,
현재 결제 결과는 세션별 최근 1건이며 서버 재시작 후 조회하는 주문·결제 이력 기능은 구현하지 않았습니다.
결제 진행 취소는 승인된 결제의 환불 기능과 별개입니다. AI 추천은 등록된 메뉴 정보와 재료를 바탕으로 하며
알레르기 안전성 판정을 제공하지 않습니다.

## 개발 환경

- Java 17, Spring Boot 4.1.1, Gradle wrapper
- MySQL
- Node.js 20.19 이상 또는 22.12 이상, npm
- React, Vite, React Router, Axios

서버는 `http://localhost:8080`, 프론트는 `http://localhost:5173`을 사용합니다.
5173 포트로 실행해야 서버의 허용된 origin과 일치합니다.

Windows 환경변수를 변경한 뒤에는 IntelliJ와 터미널을 다시 열어야 합니다.

| `DB_PASSWORD` | 필수. 사용 중인 MySQL 계정의 비밀번호 |
| `DB_USERNAME` | 선택. 기본값 `ohgiraffers` |
| `DB_URL` | 선택. 기본값 `jdbc:mysql://localhost:3306/menudb` |
| `KAKAO_REST_API_KEY` | 카카오 로그인 REST API 키 |
| `KAKAO_CLIENT_SECRET` | 카카오 앱의 Client Secret을 사용하면 등록 |
| `OPENAI_API_KEY` | AI 메뉴 추천·설명·사진 생성 |
| `KAKAOPAY_SECRET_KEY` | 카카오페이 테스트 결제 |
| `KAKAO_SYNC_ENABLED` | 간편가입/약관 설정을 완료한 경우에만 `true` |
| `KAKAO_SYNC_REQUIRED_TERMS` | 카카오 앱에 설정한 필수 약관 태그 |
| `OPENAI_TEXT_MODEL`, `OPENAI_IMAGE_MODEL` | 모델을 변경할 때 선택 설정 |
| `MENU_UPLOAD_DIR` | 사진 저장 폴더. 기본값 `./uploads/menu-images` |

카카오 개발자센터에 Redirect URI `http://localhost:8080/api/auth/kakao/callback`을 등록하세요.
AI 기능은 카카오 로그인 후 사용할 수 있습니다. 결제는 테스트 결제 설정입니다.

## DB 준비

처음 설치하는 **빈 DB**에 다음 SQL을 순서대로 적용하세요.

1. `sql/00_01_CREATE_USER_DATABASE.sql`: 예시 비밀번호 `CHANGE_ME_DB_PASSWORD`를 본인이 정한 값으로 바꾸세요. 이 값이 `DB_PASSWORD`와 같아야 합니다. 이미 계정/DB가 있다면 생략합니다.
2. `sql/00_02_DB_SCRIPT.sql`: 기본 테이블과 더미 메뉴를 만듭니다. **테이블을 삭제하고 다시 만들기 때문에 기존 데이터가 있는 DB에서는 실행하지 마세요.**
3. `sql/00_03_ADD_MENU_IMAGE.sql`부터 `sql/00_07_ADD_MENU_AI.sql`까지 번호순으로 적용합니다. 이미 해당 테이블/컬럼이 있으면 적용 여부를 확인하고 생략합니다.
4. `sql/00_08_FILL_MENU_AI_DATA.sql`: 기본 메뉴의 비어 있는 재료·설명을 채웁니다. 기존에 작성한 내용은 유지합니다.

기존 프로젝트 DB에서는 초기화 SQL을 다시 실행하지 말고, 아직 적용하지 않은 변경 SQL만 실행하세요.
실제 회원·주문·결제 데이터, DB 백업, 업로드 사진은 이 저장소에 포함하지 않습니다.

## 실행

프로젝트 루트에서 서버를 실행합니다.

```powershell
.\gradlew.bat bootRun
```

다른 터미널에서 프론트를 실행합니다.

```powershell
cd menu-app
npm ci
npm run dev
```

`http://localhost:5173/menus`에 접속하세요.
API 문서는 서버 실행 후 `http://localhost:8080/swagger-ui.html`에서 확인합니다.
macOS/Linux에서는 `chmod +x gradlew` 후 `./gradlew bootRun`을 사용합니다.

## 확인

```powershell
.\gradlew.bat test
cd menu-app
npm run lint
npm run build
```

서버 테스트에도 `DB_PASSWORD`와 테스트 가능한 로컬 DB가 필요합니다.
일반 테스트는 실제 OpenAI를 호출하지 않습니다.
실제 API 검증은 `AI_PRACTICE.md`의 `OPENAI_RUN_LIVE_TESTS` 설정을 참고하세요.
